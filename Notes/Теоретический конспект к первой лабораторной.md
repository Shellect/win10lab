## 1. Что делаем в первой работе

Связать **две IP-подсети** через маршрутизатор **MikroTik** в GNS3 и проверить связь командой `ping`.

| Роль | Устройство | Пример |
| :--- | :--- | :--- |
| Маршрутизатор | MikroTik | `ether1` / `ether2` |
| Узлы | VPCS | PC1, PC2 |
| L2 | Ethernet Switch | по одному на подсеть |

Адресация в курсе:

| Подсеть | Сеть | Шлюз (MikroTik) | Хост |
| :--- | :--- | :--- | :--- |
| 1 (Red на схеме Lab 1) | `172.16.10.0/24` | `172.16.10.254` | PC1 `172.16.10.1` |
| 2 (Blue на схеме Lab 1) | `172.16.20.0/24` | `172.16.20.254` | PC2 `172.16.20.1` |

В следующих работах те же подсети называют **blue.net** (клиенты, `.10`) и **red.net** (серверы/DMZ, `.20`).

## 2. GNS3 и эмуляция

**GNS3** — среда, где виртуальные маршрутизаторы, коммутаторы и ПК соединяются линками как в реальной сети.

**VirtualBox** — гипервизор в аудитории. Тяжёлая эмуляция часто идёт в **GNS3 VM**.

Без аппаратной виртуализации (VT-x / AMD-V) топологии работают плохо или не запускаются.

---

## 3. Коммутатор и маршрутизатор

**Коммутатор (L2)** объединяет устройства в одном сегменте: кадры по MAC-адресам. Устройства в одной подсети общаются через switch **без** роутера.

**Маршрутизатор (L3)** пересылает пакеты **между** разными IP-сетями. У каждого интерфейса — свой IP (шлюз для своей подсети).

Почему одного коммутатора мало для двух подсетей `172.16.10.0/24` и `172.16.20.0/24`: хост шлёт пакет «в другую сеть» на **шлюз по умолчанию**. Без роутера с адресами в обеих сетях пакеты между подсетями не дойдут.

---

## 4. IP-адрес, маска, шлюз

* **IP-адрес** — идентификатор узла в сети (например `172.16.10.1`).
* **Маска /24** (`255.255.255.0`) — какие биты задают «свою» сеть. Хосты с одинаковым префиксом сети (первые 24 бита) считаются соседями L3 в одной подсети.
* **Шлюз по умолчанию** — IP роутера в *вашей* подсети. Для PC1 это `172.16.10.254`, не адрес из чужой сети.

На VPCS задание вида:

```text
ip 172.16.10.1/24 172.16.10.254
```

означает: адрес хоста / маска и шлюз.

На MikroTik:

```text
/ip address add address=172.16.10.254/24 interface=ether1
```

Роутер сам получает connected-маршруты к обеим сетям, когда на интерфейсах есть адреса.

## 5. Проверка: что означает ping

| Проверка | Если успешно |
| :--- | :--- |
| `ping` своего шлюза | L2 до роутера и IP на интерфейсе верны |
| `ping` IP роутера в другой сети | Роутер отвечает «со стороны» второй сети |
| `ping` хоста в другой подсети | Работает **маршрутизация** между подсетями |

Если свой шлюз пингуется, а чужая подсеть — нет: смотрите адреса на втором интерфейсе, шлюз на втором ПК, состояние линков.

## 6. Связь с практикой Lab 1

| Понятие | Где в топологии |
| :--- | :--- |
| L2 | Switch1 / Switch2 |
| L3 | MikroTik |
| Подсеть 1 | `172.16.10.0/24`, PC1 |
| Подсеть 2 | `172.16.20.0/24`, PC2 |
| Шлюзы | `.254` на `ether1` / `ether2` |

**Итог:** первая лабораторная закрепляет основу: две подсети, шлюзы, маршрутизатор. Дальше на этой схеме появляются DNS, firewall и безопасность.
