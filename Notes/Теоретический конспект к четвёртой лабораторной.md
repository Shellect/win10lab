## 1. Цель четвёртой работы

На Alpine BIND **подписать** зону `lab.local` и увидеть в ответах записи DNSSEC (**RRSIG**, **DNSKEY**) через `dig +dnssec`. Топологию не меняем.

Отдельный валидирующий резолвер и повтор Ettercap в обязательную часть **не входят**.

---

## 2. Какую проблему решает DNSSEC

**DNSSEC** даёт:

* **целостность** — записи не подменили по пути;
* **аутентичность** — данные связаны с ключами зоны.

DNSSEC **не** шифрует DNS (запросы видны на линии). Шифрование канала — это DoT/DoH, другая тема.

| | Обычный DNS | DNSSEC |
| :--- | :--- | :--- |
| Подмена A (spoofing) | Возможна | Отвергается **при валидации** |
| Шифрование | Нет | Нет (само по себе) |

---

## 3. Ключи и записи

| Понятие | Смысл |
| :--- | :--- |
| **ZSK** | Zone Signing Key — подписывает записи зоны (A, SOA, …) |
| **KSK** | Key Signing Key — подписывает набор DNSKEY; отпечаток часто у родителя как DS |
| **DNSKEY** | Открытые ключи в DNS |
| **RRSIG** | Подпись набора записей |
| **DS** | Связка с родителем в цепочке доверия |
| **Trust anchor** | Якорь доверия валидатора (обычно корень `.`) |

Без закрытого ключа зоны Attacker не создаст корректный RRSIG — поэтому валидирующий резолвер отвергнет поддельный ответ Ettercap.

---

## 4. Цепочка доверия

В Интернете: корень → … → DS → DNSKEY дочерней зоны → RRSIG над A.

У учебной зоны **`lab.local`** нет родителя в публичном DNS. Полную цепочку до корня в GNS3 обычно не строят. В Lab 4 достаточно:

* ключи на сервере;
* подписание зоны;
* `dig +dnssec` показывает RRSIG/DNSKEY.

Чтобы spoofing из Lab 3 **гарантированно** отбивался, нужны ещё: валидирующий резолвер и доверие к ключу зоны (свой trust anchor) — это следующий уровень сложности.

---

## 5. Практика на BIND (смысл шагов)

1. Сгенерировать ZSK и KSK (`dnssec-keygen`).
2. Указать `key-directory`, включить подписание (`inline-signing` / `auto-dnssec` или `dnssec-policy` — зависит от версии BIND).
3. Перезапустить `named` (OpenRC: `rc-service named restart`).
4. Проверить: `dig +dnssec www.lab.local @172.16.20.53`, `dig DNSKEY lab.local @172.16.20.53`.

Синтаксис сверяйте с `named -v` на вашей Alpine.

---

## 6. Связь с Lab 3

| Ситуация | Результат |
| :--- | :--- |
| Зона подписана, клиент **без** валидации | Spoofing всё ещё может сработать |
| Зона подписана + резолвер **валидирует** | Поддельный A без RRSIG → отказ |
| Только `/etc/hosts` | Обход DNS для одного имени, без криптографии |

**Итог:** Lab 4 показывает DNSSEC на стороне авторитетного сервера. Защита клиента начинается там, где включается **валидация**. Подробный разбор записей и ограничений — в [DNS Spoofing и DNSSEC](../Theory/DNS%20Spoofing%20и%20DNSSEC.md).
