## 1. Цель третьей работы

На уже работающем DNS показать учебную атаку **DNS Spoofing** (подмена ответа) и простые контрмеры (`/etc/hosts`, идея DNSSEC). Только в изолированной топологии GNS3.

---

## 2. Топология

| Сеть | Кто | Роль |
| :--- | :--- | :--- |
| **blue.net** `172.16.10.0/24` | PC1 (жертва), PC2, **Attacker** | Один L2-сегмент (Switch1) |
| **red.net** `172.16.20.0/24` | Alpine DNS `172.16.20.53` | Настоящий авторитетный DNS |

Attacker обязан быть в **blue.net**: ARP poisoning работает только в одном широковещательном домене.

---

## 3. Почему обычный DNS уязвим

Клиент доверяет DNS-ответу, если совпали технические поля (в т.ч. Transaction ID). **Криптографической проверки** в классическом DNS нет: поддельный A-ответ может быть принят как настоящий.

---

## 4. DNS Spoofing — суть

**DNS Spoofing** — подмена ответа так, что имя указывает на IP атакующего (в лаборатории `www.lab.local` → `172.16.10.10` вместо `172.16.20.53`).

В нашей работе сценарий **MITM + dns_spoof**:

1. **ARP poisoning** — Attacker убеждает жертву и шлюз, что «он» — MAC другой стороны; трафик идёт через Attacker.
2. Жертва шлёт DNS Query.
3. Плагин **dns_spoof** (Ettercap) отвечает по таблице `etter.dns` быстрее/вместо настоящего сервера.
4. Клиент получает ложный IP.

```text
PC1 --ARP MITM--> Attacker --(?)--> шлюз / дальше к DNS
         ^
    поддельный DNS Reply: www → 172.16.10.10
```

---

## 5. Почему firewall MikroTik не спасает

Правила Lab 2 режут трафик **между** blue и red на роутере. Атака идёт **внутри** blue.net на L2, до (или вместо) честного запроса в red.net. MikroTik эту подмену не видит.

---

## 6. Защита (уровень Lab 3)

| Мера | Что даёт |
| :--- | :--- |
| `/etc/hosts` на клиенте | Имя не идёт через DNS — учебный «щит» |
| Контроль L2 (DAI, Port Security) | Мешает ARP poisoning (в простом GNS3 нет) |
| **DNSSEC** | Подписи записей; валидатор отвергает подделку (практика подписи — Lab 4) |
| HTTPS + проверка сертификата | Снижает ущерб фишинга, но не чинит сам DNS |

## 7. Связь с практикой

| Шаг Lab 3 | Теория |
| :--- | :--- |
| `nslookup` до атаки | Нормальный A = `172.16.20.53` |
| Attacker в blue.net | Нужен общий L2 |
| ARP + Target жертва/шлюз | MITM |
| `etter.dns` | Содержание лжи |
| `dns_spoof` | Поддельный Response |
| `/etc/hosts` | Обход отравленного DNS |

**Итог:** spoofing обманывает этап «имя → IP». Firewall между зонами полезен для DMZ, но не заменяет защиту DNS и L2. Подробности — в [DNS Spoofing и DNSSEC](../Theory/DNS%20Spoofing%20и%20DNSSEC.md).
